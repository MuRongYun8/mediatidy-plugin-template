# MediaTidy AI 识别整理 · Python 版

独立安装的 AI 整理插件，使用 Python SDK v2。入口为 `plugin.py:Plugin`，页面由 Python 动态生成，支持扫描、AI 识别、直接整理或草稿审阅、等待任务、逐文件结果及历史。

需要支持 Python 插件的 MediaTidy，宿主运行环境为 Python 3.12 和 uv 0.6.7。旧 JavaScript 插件宿主不能运行此版本。插件自身没有第三方 Python 运行依赖，普通使用和打包都不需要 Node.js。

## 安装

在 MT 插件中心选择“从仓库安装”，填写本仓库地址 `https://github.com/MuRongYun8/mediatidy-plugin-template`，分支填写 `main`。仓库根目录已包含安装需要的 Python 入口、依赖锁、清单、提示词和图标。

也可上传由 `python -m mt_plugin pack` 生成的 ZIP。安装后授权文件目录、整理方案和所需 AI 能力，再配置并启用。首次安装默认停用；AI 与 TMDB 配置沿用宿主。

当前插件版本为 `2.0.8`，修复同一部剧跨批次返回不同 TMDB ID 或季号、却都生成待确认草稿的问题。后续批次会收到同组前批的候选信息；整理前对整组检查一致性，冲突或识别不完整时整组保留原位，可手动重试。

保留 2.0.7 的自动分批：每轮最多 500 个视频，每批最多 8 个文件。100 个文件调用 13 批，106 个调用 14 批，最后一批处理余数。8 是插件的保守批量设置，不代表模型的能力上限。

超过 100 个文件需要同步更新主程序，使 `runtime.info().limits.maxWorkflowFiles` 为 500，并支持相应的草稿、任务等待和调用额度。旧主程序会收到明确的更新提示，本次不会先调用 AI 再在整理环节失败。扫描识别还需要主程序的持久文件引用恢复修复。首次使用需确保宿主支持现有 `ai.chat(singleRequest, nativeWebSearch)`；插件不增加权限、不降级为追加模型对话的旧流程。

## 使用

工作区左侧选择片源，右侧选择整理方案、处理方式并填写可选的补充说明。直接整理会按所选方案执行文件操作；处理方式选择“整理前让我确认”时，只生成待确认结果；核对作品、季集和目标位置后，点击确认才执行文件整理。整轮最多 500 个视频；手机上两个区域按顺序上下排列。

500 个视频是所有目录与直接选中文件的合计容量。多目录汇总超限时，页面显示 `FILE_LIMIT_EXCEEDED`、已发现的数量和分批选择提示；尚未读取的扫描页可能还有更多文件，因此数量标为“至少”。不会只处理前 500 个，也不会对不完整扫描提供“重试识别”；旧版失败历史保留原状，更新后开始新一轮即可。批次按顺序处理，进度显示当前批次/总批次；不额外并发调用 AI。主程序原有的超时与取消仍然生效，实际完成时间取决于模型搜索及整理耗时。

识别明细按每页 20 个文件读取，搜索与排序作用于当前页。运行摘要最多保留前 20 行，完整结果仍保存在插件存储中，通过翻页查看。每批最终回答单独保存，按每页 10 批读取，兼容旧版直接保存在流程中的回答；避免大任务因结果或流程存储过大而中止。

同剧一致性：对同一授权根、同一目录、相同剧名前缀与文件季号中明确标记 `E012`、`EP12`、`S01E12` 的分集文件建立组。不同根目录、不同目录、不同剧名前缀或文件季号分开；不凭“在同一目录”合并所有视频，纯数字文件名及多集合并文件不自动归组。后续请求携带该组前批的候选作品信息，但不会把第一次回答视为必然正确，也不会复制前一集的集号。

同组文件在全部批次完成前显示“等待同剧核对”，暂不生成草稿或提交整理。如果出现 `2661 / S30` 与 `155371 / S1` 这类不同身份，整组显示“同剧识别冲突，未整理”，保留各自原始结论并允许整组重试；不按首个结果或多数结果强行覆盖。缺少有效回答的同组文件也须一起重试。无关联的文件和其他完整、无冲突组仍可处理。旧版本已经生成的草稿不自动改写；旧记录存在冲突时，请不要直接确认混合身份的草稿，更新后开始新一轮或手动统一作品与季号。

每批最多 8 个文件，在一次模型 HTTP 请求内执行原生网页搜索，再返回作品名、原文名、首映/首播年份、类型、TMDB ID、季集、简短说明和可用来源。服务商内部可以搜索多次，插件不追加模型对话。必须支持 Responses `web_search`，在 MT 设置中启用 AI 联网，并已授权 `ai.web.search` 和 `tmdb.read`。未知、缺少有效 ID、季集不完整的结果标为“未识别”；JSON 格式错误、重复引用或缺失结果标为“失败”并给出解析诊断。文件均保留原位；其他有效文件和后续批次继续处理。插件严格按 fileRef 对应文件，不按回答顺序或文件名猜测对应关系，也不从残缺 JSON 中提取部分对象。

运行结果下方可展开“AI 原始回答与诊断”，查看每批匹配数量、重复/无效引用数量以及模型最终回答预览。回答按纯文本显示，最多保留前 8 KB；超出时明确提示截断。此处不保存模型推理过程，也不把原文写入普通日志。旧记录没有保存的回答无法补回；没有拿到最终回答的请求也没有原文。运行中可点击“刷新回答”重新读取。格式错误不代表模型无法识别作品，可先查看回答，再决定是否手动重试。

AI 结论会先显示。有完整作品信息和有效 ID 就通过现有 `tmdb.detail` 核对，不因缺少搜索引用而拦截（同次运行按类型和 ID 去重查询）。ID、类型必须一致，标题/原文名经 Unicode、大小写、标点规范化后至少匹配一个，首映/首播年份必须一致；缺失、冲突或详情读取失败均跳过，保留原结论并显示差异。随后按 AI 提供的 ID 交给 MT 整理。MT 为命名和刮削获取该 ID 的元数据，保留方案、权限、路径和必要业务校验；不会根据片名搜索或更换 ID。ID 无效、元数据获取失败或条件不满足时显示具体错误，同时保留 AI 结论。排队不表示整理成功，任务完成后更新逐文件结果；提交结果未知时不自动重试。

默认提示词结合中外文别名、原文名、目录与平台线索辨别同名作品，避免把英文发布名直接当成原文名。TX/WeTV、NF/Netflix 等仅作为辅助线索；明确的 S01E06 可提供季集编号，不要求额外找到季集网页。有歧义仍返回未知。未确认 ID 时保留已知作品信息，不编造 ID。

每批只允许一次模型 HTTP 请求；原生搜索必须有已完成记录。超时、空回复、非法 JSON、参数不兼容或工具不支持均不自动重发；本批未知不触发补查，不降级为普通聊天或第三方搜索。请求统计分别记录模型响应、模型排队、整理准备与提交耗时；文件结果单列元数据核对耗时，并记录从整理提交至完成的耗时（含排队，确认模式仅记录草稿准备时间）。实际速度取决于模型、TMDB 和存储服务。

运行结束后，识别失败或未识别的文件可以点击“重试识别”，无需重新选择片源、整理方案或填写补充说明。重试会重新检查文件和读取授权，沿用原处理方式，生成独立运行记录；原结果保留。已识别、已提交整理、待确认及提交结果不明的文件不在重试范围内。同一记录只创建一次重试，重试后仍失败时从新记录继续重试。扫描续接报 `AI 批次文件引用无效` 时，需使用包含持久文件引用恢复修复的 MT 主程序。

默认提示词随更新升级，仅替换仍使用旧默认值的配置；用户自定义提示词保留。附加的输出协议要求原生搜索、单次回答，并明确引用为可选项，取代旧提示词中“必须有 TMDB 引用才能识别”的要求；不恢复多轮工具对话。

开始运行后，页面集中展示进度与逐文件结果；作品、季集、TMDB ID、处理状态和识别说明直接显示，无需展开详情。服务商确实提供对应引用时显示“TMDB 搜索依据”；缺引用但核对成功时显示“TMDB 核对条目”和“TMDB 核对通过”，不把模型自写链接当作搜索证据。核对失败不会产生可确认草稿。有 MT 核验记录时，同时展示核验后的作品与错误；点击“修正或确认整理”可编辑并确认。旧版历史记录兼容显示文件路径和原始摘要，未保存的作品字段会明确说明；升级不会自动重新识别或提交旧结果。日志和运行记录可通过宿主顶部入口查看。完整提示词从“高级设置”打开侧面板编辑并保存。页面布局在 `page.py`，识别与整理逻辑在 `plugin.py`。开发时的默认提示词只有一个来源：`prompts/default.txt`，通过同步脚本写入安装清单。

## 开发与验证

从同版本 MT 插件中心下载“开发 Skill 完整包”，其中 `mediatidy-plugin-development/references/sdk` 是 Python SDK 源码。用 Python 3.12 创建开发环境，然后安装该 SDK、固定版本的 uv 和 mypy：

```sh
python -m pip install /path/to/mediatidy-plugin-development/references/sdk uv==0.6.7 mypy
python scripts/sync-prompt.py --check
python -m unittest discover -s tests -v
python -m mt_plugin pack
```

修改默认提示词后运行 `python scripts/sync-prompt.py` 再打包。产物默认位于 `dist/official.ai-organize-2.0.8.zip`。测试使用内存宿主，覆盖缺引用仍核对 ID、错误 ID 拦截、别名/平台文件输入、部分成功、单次请求、取消、重复提交、回答格式兼容、原文诊断及多目录扫描数量边界；不调用真实 AI、云盘或整理服务，不代表真实模型一定能识别这些作品。

在 MT 源码目录下联调页面时，还可运行 `node --test tests/page.test.cjs`，通过宿主实际的 UI 表达式求值器检查新版及历史结果。独立检出时用 `MT_UI_SCHEMA` 指定宿主 `plugin-ui-schema/index.cjs` 的绝对路径，`PYTHON` 指定安装了 SDK 的 Python 解释器。此项联调检查需要 Node.js，不影响插件运行与打包。

目录与流程说明见 [插件开发说明](docs/README.md)。
