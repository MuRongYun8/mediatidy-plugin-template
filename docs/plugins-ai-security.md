# AI 识别整理模板与安全规范

## AI 自主识别（模板 v1.2.0）

每批最多 8 文件、总计最多 100 视频。只发送原始文件名、授权根内相对路径、随机 fileRef 和用户说明。插件通过 ai.chat 向模型提出识别任务，不预切词、不猜作品、不调用内置识别 Agent；不固定查询顺序、搜索词、候选筛选或识别轮次。AI 可以直接回答，也可以自主调用公开搜索、TMDB 搜索和详情工具。

prompt 是完整可编辑任务；旧 extractionPrompt / selectionPrompt 保存在宿主 retiredConfig 中，但不进入新运行配置、不自动拼接。模型返回作品、年份、类型、季集、简短说明和可选 TMDB 条目。按 fileRef 对应，重复/外来/缺失引用单独待处理；所有条目仍由 MT 查询实际详情、季集和资源。

ai.chat 仅传输对话和函数声明，不执行工具。模板显式分发 web_search / tmdb_search / tmdb_detail 到对应 SDK，禁止动态 SDK 方法调用、任意 URL、组织提交和确认工具。工具参数白名单验证，后端每次再验权限、安装修订和配额；HTML、原型污染键和模型指令不提升权限。网页摘要与文件名都按不可信文本处理，不展示模型内部推理。

ai.web.search 是独立授权能力，仅查询已配置的原生联网或 Tavily，不提供缓存、配置或凭据。只返回最多 5 条公开标题、摘要、来源链接，不抓取结果网页；模型和搜索服务可能接收文件线索和查询词。不开启联网、不支持工具、查询失败必须明确反映，不能伪装查询成功。

每批最多 6 次 ai.chat；每运行 ai.chat 与 ai.complete 合计最多 78 次（旧 ai.complete 单方法仍最多 32 次），公开搜索最多 32 次。共享模型限流和运行取消、30 分钟运行时限。达到限制保留已有结论，缺项待重试；不会重放整理。工具不支持时剩余轮次降级为直接识别，不自动切换模型。

recognition 仅供展示，匹配或核验失败不抹掉 AI 结论，不替代可信 media。公开来源只从实际工具返回的链接中选择，以纯文本显示，不允许模型随意插入可执行 URL。

## 核验与人工确认

宿主查询 TMDB 详情并核对媒体类型，剧集还查询目标季的实际集号。模板 v1.0.1 对模型未提供或返回 null 的季数默认补第 1 季，并在依据中明示；明确的第 0 季和其他有效季数保留，异常季数不覆盖，集号不猜测。默认值仍需通过实际季集核验，旧草稿不自动修改。电影带季集、剧集缺少集号或有异常季数、不存在的季集、无候选或多集合集均为待处理。详情已查到而季集失败时保留作品名称与年份，不能因此提交。多集合集不能切成第一集，不在模板中提供解除 unsupported 的按钮；请回 MT 人工处理。

用户可搜索其他作品、改 TMDB ID、类型、方案和季集，再保存核验。未勾选文件跳过；只有 ready 项可选。确认弹窗展示逐文件作品/年份/类型/ID/季集、方案/目标目录/传输方式；明确同意后才逐文件调用现有手动整理队列。最终命名仍由真实整理流程决定，不提前伪造依赖 ff 的文件名。

确认冻结 revision。编辑、版本/配置/授权变化、方案变化或可检测文件变化都会阻止旧确认。封存覆盖是 MT 弹窗的独立选项，插件不能设置。已入队、执行中、成功、失败、取消分别展示。

部分入队失败保留成功项，重复点击不会重复提交已成功项。进程重启不会重放识别或整理，未完成提交变为 submission_unknown，需要人工查任务中心。仅重试待处理项仅重跑识别；已有整理任务仍由原 MT 机制管理。

## 禁止的数据与入口

- 不向任何插件提供原始 ffprobe JSON、远程 ff 记录、本地 ff 缓存、缓存导出、SHA1 查询或全局日志。
- 不提供云盘 Cookie、Pickcode、播放/下载直链、模型密钥、通知渠道凭据、数据库或宿主文件内容。
- 不导出内部服务对象；所有能力使用专门 JSON 白名单。新增字段前必须确认不会将敏感 drive/模型/配置结构间接序列化。
- HTTP 默认拒绝；不得借公开地址、DNS 重绑定、重定向、私网授权、IPv6 元数据地址访问 MT/ff/云元数据。
- 禁止下载脚本执行、动态 require、npm 生命周期或插件自带网页脚本。分发 JS 仅运行在无 Node 环境的工作进程。

插件日志、错误和结果也必须遵守这些规则。宿主只返回专门错误摘要与白名单任务信息，不向插件暴露 MT 核心任务原始错误/日志。

## 验证与部署

Go 安全测试覆盖包穿越/链接/超限、摘要篡改、源地址与 SSRF 边界、独立子进程、无 Node/Go/确认入口、取消与安全错误、文件越权与去重/上限、伪造或过期确认、修改后执行值、部分入队/幂等、授权撤销、存储隔离/配额、任务会话与中断恢复。AI 和 TMDB 使用本地模拟服务，测试不连接真实模型、云盘或 ff 服务。模板 mock 测试覆盖错序/漏项/重复/虚构候选/多集/异常模型响应。

正常二进制和 release 标签都应验证插件模块，发行程序工作进程入口保留 runtimeguard。容器继续使用原有只读根、最小权限与可写 data 卷，插件包位于数据库同目录下的 plugins/packages，安装时无需写系统目录。禁止为插件运行放开 Docker 权限、宿主目录、加固或许可证检查。生产 release 容器端到端验证必须在实际 Docker Engine 和原发行构建链执行，普通 Windows 运行不等同于这项验证。

宿主对大小/mtime 的文件检查存在同大小同时间替换的检测限制。独立进程的内存采样和 Go 软预算存在采样超调，不宣称完整 OS 隔离；对完全不信任插件或高敏感部署，应在容器/虚拟机层增加独立限制，并审阅已固定的源提交。

组件页面、Logo、资源安装与 FF 摘要能力的当前契约见 [组件协议 v1](plugins-component-protocol.md)。
