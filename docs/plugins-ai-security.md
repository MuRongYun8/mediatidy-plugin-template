# AI 识别整理模板与安全规范

## 识别策略

模板以文件为独立处理单位，每批 8 项，最多 100 个视频。第一轮仅发送文件名、授权根内相对路径、当前运行的随机 fileRef 与用户补充说明，提取 name/year/mediaType/season/episode/multiEpisode。宿主配置的模型服务是用户选择的外部数据接收方，安装权限和运行页会提示此数据用途。

第二轮只传第一轮线索与 MT 实际查询的 TMDB 候选，要求返回 fileRef、真实候选 ID、媒体类型、uncertain 和简短 reason。插件再次检查 ID/类型是否出现在该文件的候选集合；缺项、重复 fileRef、外来引用、冲突、错误类型或不确定均不能成为默认可提交项。模型返回顺序不影响配对，绝不用数组下标关联文件。

两轮补充策略可在插件配置修改（extractionPrompt / selectionPrompt）。修改基础提示词可编辑源码并重新构建发布。提示词、文件名、用户输入、候选简介和模型输出都当作不可信数据；不能将这些数据提升为命令、路径、权限或确认。候选选择只决定草稿，模型“高置信度”“已确认”等文字不改变宿主校验。

## 核验与人工确认

宿主查询 TMDB 详情并核对媒体类型，剧集还查询目标季的实际集号。电影带季集、剧集缺少季集、不存在的季集、无候选或多集合集均为待处理。多集合集不能切成第一集，不在模板中提供解除 unsupported 的按钮；请回 MT 人工处理。

用户可搜索其他作品、改 TMDB ID、类型、方案和季集，再保存核验。未勾选文件跳过；只有 ready 项可选。确认弹窗展示逐文件作品/年份/类型/ID/季集、方案/目标目录/传输方式；明确同意后才逐文件调用现有手动整理队列。最终命名仍由真实整理流程决定，不提前伪造依赖 ff 的文件名。

确认冻结 revision。编辑、版本/配置/授权变化、方案变化或可检测文件变化都会阻止旧确认。封存覆盖是 MT 弹窗的独立选项，插件不能设置。已入队、执行中、成功、失败、取消分别展示。

部分入队失败保留成功项，重复点击不会重复提交已成功项。进程重启不会重放识别或整理，未完成提交变为 submission_unknown，需要人工查任务中心。仅重试待处理项仅重跑识别；已有整理任务仍由原 MT 机制管理。

## 禁止的数据与入口

- 不向任何插件提供原始 ffprobe JSON、远程 ff 记录、本地 ff 缓存、缓存导出、SHA1 查询或全局日志。
- 不提供云盘 Cookie、Pickcode、播放/下载直链、模型密钥、通知渠道凭据、数据库或宿主文件内容。
- 不导出内部服务对象；所有能力使用专门 JSON 白名单。新增字段前必须确认不会将敏感 drive/模型/配置结构间接序列化。
- HTTP 默认拒绝；不得借公开地址、DNS 重绑定、重定向、私网授权、IPv6 元数据地址访问 MT/ff/云元数据。
- 禁止下载脚本执行、动态 require、npm 生命周期或插件自带网页脚本。分发 JS 仅运行在无 Node 环境的工作进程。

插件日志、错误和结果也必须遵守这些规则。宿主只返回专门错误摘要与白名单任务信息，不向插件暴露 MT 核心任务原始错误/日志。

## 验证与部署

Go 安全测试覆盖包穿越/链接/超限、摘要篡改、源地址与 SSRF 边界、独立子进程、无 Node/Go/确认入口、取消与安全错误、文件越权与去重/上限、伪造或过期确认、修改后执行值、部分入队/幂等、授权撤销、存储隔离/配额、任务会话与中断恢复。AI 和 TMDB 使用本地模拟服务，测试不连接真实模型、云盘或 ff 服务。模板 mock 测试覆盖错序/漏项/重复/虚构候选/多集/异常模型响应。

正常二进制和 release 标签都应验证插件模块，发行程序工作进程入口保留 runtimeguard。容器继续使用原有只读根、最小权限与可写 data 卷，插件包位于数据库同目录下的 plugins/packages，安装时无需写系统目录。禁止为插件运行放开 Docker 权限、宿主目录、加固或许可证检查。生产 release 容器端到端验证必须在实际 Docker Engine 和原发行构建链执行，普通 Windows 运行不等同于这项验证。

宿主对大小/mtime 的文件检查存在同大小同时间替换的检测限制。独立进程的内存采样和 Go 软预算存在采样超调，不宣称完整 OS 隔离；对完全不信任插件或高敏感部署，应在容器/虚拟机层增加独立限制，并审阅已固定的源提交。
