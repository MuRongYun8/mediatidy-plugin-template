# 发布、升级与排错

[返回 Wiki](README.md)

## 发布自己的插件

1. 修改独立插件 ID、作者和版本；保留 SDK v1，尽量只申请必要权限。
2. `npm ci --ignore-scripts`，然后 `npm run check`。确保测试模拟模型、TMDB 与云盘。
3. 提交 `plugin.json`、`src/`、`dist/index.js`、`sdk/`、脚本、测试、锁文件与文档。不要提交 node_modules、密钥、日志、数据库或真实文件列表。
4. 推送到 GitHub/Gitee 公开仓库，创建版本标签，例如 `v1.2.0`。已发布标签不要移动或覆盖；新内容使用新版本。
5. 在 MT 用仓库和标签检查安装，确认源提交、权限、配置与默认值，并用测试媒体走一遍预览确认流程。

MT 不执行 npm install、构建或仓库脚本。仅源码但缺少 dist 的仓库不能安装。SDK 不兼容主版本直接拒绝；升级不运行配置迁移脚本，新字段应提供兼容默认值。v1.2.0 使用 ai.chat / ai.web.search，新宿主支持这两项能力后才可安装。

## 升级与回退

卡片更多菜单或设置页点击“检查更新”。默认沿用安装来源和引用，版本标签固定时需要手动填新标签，分支则解析到新提交。检查目标版本／提交和新增能力，重新授权后安装。新增能力后保持停用，检查设置再启用。已移除的配置字段保存在 retiredConfig，不传给新脚本；回退会恢复对应版本字段并重新校验。没有检查前 UI 不声称已是最新。

当前与目标内容摘要相同时不重复安装。安装失败保留旧版；保留一个上一版本供回退。回退不兼容配置时拒绝，成功后停用，需检查再启用。若想从远程源改为内置副本，可能需要先卸载，因为同名插件不能随意更换来源；先记录所需配置与授权。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 仓库读取失败 | 检查公开 HTTPS 根地址、分支／标签和网络；不要填写 tree/main 页面地址 |
| Fake-IP 网络无法安装 | GitHub/Gitee API、归档域名应使用正常公网 DNS；198.18.x.x 等保留地址会被拒绝。不要关闭 SSRF 检查 |
| 未找到 dist 或清单 | plugin.json 和 dist/index.js 必须位于仓库根及指定入口，重新构建并提交 |
| 查询工具不可用 | 检查 ai.web.search 授权及 MT 联网开关；模型不支持工具时降级直接识别，界面不会声称已联网 |
| AI 失败／未配置 | 在 MT 设置启用模型并配置 Base URL、模型名和密钥；插件不接受独立密钥 |
| 无权限或目录列表为空 | 检查能力勾选、目录授权、插件启用及目录当前是否存在 |
| 整理方案不匹配 | 检查文件与方案存储类型、方案启用状态及授权 |
| 剧集缺季集 | 无季数的新识别默认 1，缺集号仍待修正；旧草稿需重识别或手动填入 |
| 作品已匹配却待处理 | 看单独的核验错误；常见是目标季／集不存在、方案暂停或多集合集 |
| 修正按钮不可点 | 识别尚未完成、插件停用或多集合集不支持；按旁边提示处理 |
| 已入队但未整理成功 | 排队只是提交阶段，查看实际任务状态；错误去 MT 任务中心核对 |
| 提交超时／结果未知 | 刷新并核对任务，不重复点击或自动重放，重启后尤其如此 |
| 保存设置后旧草稿失效 | 配置／权限／版本改变安装修订，是预期保护，重新识别确认 |
| 定时输入为空 | 先在运行页选择文件和参数，到设置勾选“替换定时输入”再保存 |

## 维护与调试

运行日志按能力记录成功或失败，插件自行日志要使用安全摘要。停用会中断识别，但不会取消原 MT 整理队列；取消操作仍可在结果中执行。清理运行记录前确认所属任务已结束；清理未使用版本保留当前和回退版本。

问题反馈应包含模板版本、SDK 版本、宿主版本、失败能力和已脱敏摘要。不要附 Cookie、模型密钥、远程 ff 数据、完整直链或全局日志。生产 Docker 验证继续使用 MT 原发行链路，不为插件放宽加固、许可证、只读根或权限。
